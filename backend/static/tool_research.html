Read this first

  • On 29 August 2026 we researched 18 tools to find out which ones could help turn a film script into storyboard pictures.
  • The big finding: no single tool does the whole job. You need a team of tools, each doing one part, like a film crew.
  • The research's top pick, ComfyUI running the Flux.1-dev image model, is still the heart of the system today.
  • Many other picks changed once we actually built and tested them. Every card below shows what we use now (checked against the code on 1 October 2026).

The job, in plain words

You give the app a screenplay. It gives you back a storyboard: a big sheet of pictures, one for each camera shot, with notes under each one. Making a film needs a crew, and so does this. Here is our crew:

  • The script readerSplits the script into scenes, lines and characters.
  • The directorDecides the shots: close-up or wide, which lens, how the camera moves.
  • The artistDraws each shot as a realistic picture.
  • The face keeperMakes sure RAM always looks like RAM and SITA like SITA.
  • The checkersSpot mistakes: missing people, broken hands, wrong clothes.
  • The board builderLays everything out on one sheet you can download.

How we judged a tool

The research gave every tool a score out of 10 by asking five simple questions:

  1. Is it free? We wanted no fees for every picture we make.
  2. Can our code control it? In other words, does it have an API, a way for programs to talk to it? Our pipeline is automatic, so nobody clicks buttons in the middle.
  3. Does it do one of our jobs? Some good tools solve a different problem.
  4. Is someone still looking after it? Was it updated in 2025–2026, or has it been abandoned?
  5. Is the licence safe? The licence is the rulebook that says how you may use it. Are we allowed to use it in a product we might sell one day?

A tool could be great software and still score low. If a person has to click its buttons, it can't be part of an automatic pipeline.

August plan vs today

The left side is what the research recommended. The right side is what we actually use now. The word on each arrow says what happened.

What changed since the research, and why

  • Research said: use Gemini 2.5 Flash as the text AI.
    Today: Groq · gpt-oss-120b. The project rule became "never use Gemini". Groq is very fast and returns clean, structured answers.
  • Research said: PhotoMaker V2 is the best face tool, with "no licence landmine".
    Today: USO. That claim turned out to be wrong. PhotoMaker V2 depends on InsightFace face models, which are for research only, and it is built for a different image model (SDXL), not Flux.
  • Research said: use UNO / UMO for shots with several characters.
    Today: USO. The community add-on that runs UNO inside ComfyUI had a bug: every time we gave it a reference photo, it made a flat, broken picture. USO comes from the same company and is UNO's newer version. It runs on ComfyUI's own built-in parts, so there's no outside add-on to break.
  • Research said: Diffusers is the library "underneath ComfyUI".
    Today: not used. This was a mistake in the research. ComfyUI has its own engine and doesn't use Diffusers, so we never needed it.
  • Research said: ControlNet is the main way to control the camera.
    Today: switched off. We control framing with careful prompt wording, plus a first pass that uses only words. The ControlNet code is there, but nothing turns it on, and its model file isn't downloaded.
  • Research said: InsightFace / DeepFace can check faces inside our own quality checks.
    Today: YuNet + SFace (two small OpenCV models). They're free for commercial use, so even our checking step is licence-safe.
  • Research said: use screenplay-tools to read script files.
    Today: our own parser. It reads Fountain, Final Draft (FDX), PDF, Word and plain text. It keeps the research's key advice: no AI for this exact step.
  • Research said: run the image AI on a rented or owned GPU.
    Today: a free Kaggle GPU, reached through a free Cloudflare tunnel.
  • Research didn't mention this.
    Flux.1-dev's own licence is "non-commercial". Pictures it makes can be used commercially, but running the model inside a paid product needs a commercial licence from its makers, Black Forest Labs. This is the biggest thing to fix before selling the product.

Tools we use today

These 11 tools make every storyboard you see in the app.

From the research· 4 tools

ComfyUI running Flux.1-dev

Using now

Research score 9.5 / 10 · ComfyUI: GPL-3.0 (free) · Flux.1-dev: non-commercial licence ⚠

What it is: A program that runs image-making AI. You connect small boxes called nodes, like LEGO, into a recipe for a picture. Our backend sends it that recipe over the internet.

Think of ComfyUI as the kitchen and Flux.1-dev as the chef who paints the picture.

How we use it: It runs on a free Kaggle GPU. Every shot is made in 3 passes. First it draws the scene from words only, to get the framing and action right. Next it cleans up details like hands. Last, it finds each face and repaints it using that character's reference photos.

Hugging Face Hub the model library

Using now

Research score 7 / 10 · Free to download from

What it is: A huge website where people share AI models, like an app store for AI.

It's the shelf where we pick up our tools before work starts.

How we use it: Every time the Kaggle machine starts, it downloads Flux.1-dev, its text readers and the USO add-on from here (about 40 GB). As the research advised, we don't use Hugging Face's paid service that runs models for you.

OpenCV picture toolbox

Using now

Research score 6 / 10 · Apache-2.0 (free, commercial-safe)

What it is: A free, very popular library of code for working with images.

A Swiss-army knife for pictures.

How we use it: It runs YuNet, which finds faces, and SFace, which says whose face it is (see their card). It also compares colours between shots, to catch lighting that suddenly changes.

Changed since the research: it was meant to be one small ingredient. It ended up running our face check too.

CLIP picture "fingerprints"

Using now

Research score 7 / 10 (scored together with DeepFace) · MIT (free)

What it is: A model that turns a picture into a list of numbers that describes how it looks. Two similar-looking pictures get similar numbers.

Like a fingerprint for the whole look of a picture.

How we use it: In the continuity check. It asks: does this shot's style, costume and place still look like the other shots in the same scene? If not, the shot is flagged for review.

Added laterNot in the research· 7 tools

USO by ByteDance

Using nowAdded later

Apache-2.0 (free, commercial-safe) · Runs inside ComfyUI

What it is: An add-on for Flux that looks at reference photos of a character and keeps that person looking the same in new pictures.

Like pinning a photo of the actor next to the painter's easel.

How we use it: In the last pass, each face in the picture is repainted with USO, using that character's reference photos. It's built only from ComfyUI's own built-in nodes, with no outside add-on.

Replaced: PhotoMaker V2, UNO / UMO, and InstantID / IP-Adapter.

YuNet + SFace face finder + face checker

Using nowAdded later

YuNet: MIT · SFace: Apache-2.0 · Both run through OpenCV on our own computer

What they are: Two small face models. YuNet finds every face in a picture. SFace makes a "face fingerprint" and compares it with RAM's and SITA's reference photos.

YuNet says "there's a face here". SFace says "that's SITA".

How we use them: They decide which face to repaint as which character. Then they mark the result on a 0–1 scale, where higher means more alike. On closer shots, a face scoring below 0.55 fails the check and the shot is made again.

Replaced: InsightFace and DeepFace, which the research suggested for this job.

MediaPipe by Google

Using nowAdded later

Apache-2.0 (free) · Runs on our own computer

What it is: A set of small models that find faces and hands, and the points on each finger.

A quick doctor's check-up for hands: are there five fingers, and are they the right lengths?

How we use it: The first, free quality check on every picture. It counts faces and hands and catches broken fingers (a common AI mistake), all before we ask the bigger AI checker.

Groq gpt-oss-120b + qwen3.8-27b

Using nowAdded later

Online service with a free tier (speed limits apply)

What it is: Groq is a company that runs AI models very fast in the cloud. We use two of its models:

• gpt-oss-120b is the "brain" for text. It understands the story, plans the shots and drafts the captions under each picture.
• qwen3.8-27b is the "eyes". It looks at each new picture and reports what's wrong: someone missing, bad hands, wrong clothes or the wrong shot size.

A very fast phone line to two experts: a writer and an inspector.

Replaced: Gemini 2.5 Flash, from the original plan. Project rule: never use Gemini.

Kaggle free cloud GPU

Using nowAdded later

Free · Weekly limit on GPU hours · Each session stops after 12 hours

What it is: A website that lends you a powerful graphics card (GPU) in the cloud for free. Image AI needs a GPU; a normal laptop is far too slow.

Borrowing a professional studio for the day instead of buying one.

How we use it: Our setup notebook installs ComfyUI, downloads the models and starts it, all automatically, on a Tesla T4 GPU.

Replaced: the research's "rented or owned GPU".

Cloudflare tunnel quick tunnel

Using nowAdded later

Free · No account needed

What it is: A tool that gives a computer hidden inside Kaggle a temporary public web address.

Like a temporary phone number, so our backend can call the Kaggle machine.

How we use it: Our backend sends picture recipes to ComfyUI through this address. The address changes every session, so the notebook publishes the new one where we can read it.

ReportLab + Pillow the board builders

Using nowAdded later

ReportLab: BSD · Pillow: open source · Both free

What they are: Two Python libraries. ReportLab makes PDF files, and Pillow makes and edits images.

The printer and the photo lab.

How we use them: When you click Compose Boards, ReportLab builds a sharp PDF with every picture at full quality. Pillow builds a 7200-pixel-wide PNG and a quick preview. The research only mentioned ReportLab in passing, for a shot-list export.

Built in, but switched off

ControlNet guide-image add-on

Switched off

Research score 8.5 / 10 · Licence depends on the model file

What it is: An add-on that makes the image AI follow a guide picture, such as a depth map or a stick-figure pose.

Like tracing paper under a drawing.

Where it stands: The code to plug it in exists (for shots with no characters). But nothing turns it on, and the model file isn't downloaded on Kaggle. Framing comes from careful prompt wording and the words-only first pass instead.

Changed since the research: it was ranked #3 as "the main way to control the camera". In practice, we didn't need it yet.

Tried, then replaced

PhotoMaker V2 by TencentARC

Replaced

Research score 8.5 / 10 · It was the research's #1 face tool

What it is: A tool that makes a new picture of a person look like their reference photo, without any extra training.

Why we dropped it: It relies on InsightFace face models, which are research-only, and it is built for SDXL, a different image model from our Flux.

Replaced by: USO.

Changed since the research: the research said it had "no licence landmine". It does, through InsightFace.

UNO / UMO by ByteDance

Replaced

Research score 8 / 10 · Apache-2.0

What it is: A model that keeps several characters looking right when they appear together in one picture.

Why we dropped it: We tested it on the real GPU. The community add-on that runs UNO in ComfyUI had a bug: with any reference photo, it made a flat, broken picture.

Replaced by: USO, the same company's newer model, which runs on ComfyUI's built-in parts.

IP-Adapter-FaceID / InstantID face-copy add-ons

Replaced

Research score 4 / 10 · Their face models: research-only licence

What they are: Add-ons that copy a face from a photo into a new picture.

Why we dropped them: The very first version of the app used them (Module 31). We removed them because their face models may not be used in a commercial product.

Replaced by: USO for drawing faces, and YuNet + SFace for checking them.

Looked at, not used

Good to know about. Each card says in one line why it doesn't fit.

Hugging Face Diffusers image AI library

Not used

Research score 9.5 / 10 · Apache-2.0

What it is: A Python library for running image AI models from your own code.

Why not: ComfyUI already does this job, with its own engine.

Changed since the research: the research said Diffusers runs underneath ComfyUI. It doesn't, so we never needed it.

screenplay-tools script file reader

Not used

Research score 8 / 10 · MIT

What it is: Free code that reads screenplay files (Fountain and Final Draft).

Instead: we wrote our own parser. It reads Fountain, Final Draft (FDX), PDF, Word and plain text, without AI, which matches the research's advice.

InsightFace face recognition

Not used

Research score 6 / 10 · Code MIT, but face models research-only ⚠

What it is: The best-known free face-recognition toolkit.

Why not: We avoided it on purpose. Its trained face models are for research only. YuNet + SFace do the job with commercial-safe licences.

DeepFace face comparison

Not used

Research score 7 / 10 (scored together with CLIP) · MIT

What it is: A simple Python wrapper around several face-recognition models.

Why not: SFace already compares faces for us, so one tool was enough.

Story2Board research project

Not used

Research score 7 / 10 · MIT

What it is: A university research project that makes storyboard pictures with consistent characters.

Why not: It's small, young and run by one person. Our ComfyUI + USO pipeline already does this job.

Boords storyboard website

Not used

Research score 5 / 10 · Paid (the API needs a paid plan)

What it is: A paid website for making and sharing storyboards with clients.

Why not: It costs money and doesn't solve face consistency. We built our own Board Studio, with high-quality downloads.

StudioBinder production planner

Not used

Research score 2 / 10 · Paid tiers

What it is: A website for planning a shoot: schedules, call sheets and shot lists.

Why not: It has no API, so our code can't talk to it. We only borrowed ideas for our shot-list fields.

OpenMMLab vision toolbox

Not used

Research score 2 / 10 · Apache-2.0

What it is: A big collection of computer-vision tools.

Why not: Its development has largely stopped since late 2023. We didn't want to depend on code that isn't being updated.

WonderUnit Storyboarder drawing app

Not used

Research score 2 / 10 · Licence unclear

What it is: A free desktop app for sketching storyboards by hand.

Why not: It has no API, its licence is unclear and it's barely maintained. We only looked at it for ideas.

FrameForge Studio 3D previz app

Not used

Research score 1 / 10 · Paid, closed source

What it is: A paid desktop app for placing virtual cameras in a 3D set.

Why not: There is no way for code to control it. It's useful only as an idea for how to describe lenses.

PySceneDetect video cut finder

Not used

Research score 1.5 / 10 · BSD-3

What it is: A tool that finds the cuts in a finished video.

Why not: It solves the wrong problem. Our pipeline works with words and still pictures, not video.

Honest warnings, and what actually happened

  • "Keeping the same face across hundreds of pictures is still an unsolved research problem."True. It took three tries (InstantID, then UNO, then USO), plus a face-repaint pass and a face checker. Today RAM's faces match his reference with an average score of 0.58 (it was 0.44 before the repaint pass), and SITA's average 0.74.
  • "No free model lets you set the camera directly."True. We steer framing with careful wording and a words-only first pass. A few shots still come out at the wrong size, which is why the board can crop (reframe) a picture.
  • "InsightFace face models are research-only."Avoided. We used YuNet + SFace instead, which are free for commercial use.
  • New, and not in the research: Flux.1-dev's own licence is non-commercial.The pictures may be used commercially, but running the model inside a paid product needs a commercial licence from Black Forest Labs. Sort this out before selling the product.
  • "Free hosted AI services won't handle the volume."True. We used a free Kaggle GPU instead. It has its own limits: a weekly hour allowance, a 12-hour session limit, and a new tunnel address every time.
  • "Avoid OpenMMLab, Storyboarder and PySceneDetect."Followed. None of them are used.

Words explained

AI model
A trained "brain" file that does one kind of job, like writing text or drawing pictures.
API
A doorway that lets one program send requests to another, with no person clicking buttons.
GPU
A graphics card. It does thousands of small calculations at once, which image AI needs.
Open source
Software whose code is public and free to use, within its licence rules.
Licence
The rulebook for a tool. "Non-commercial" means you can't use it in something you sell.
Node (ComfyUI)
One small box in a ComfyUI recipe, such as "load model" or "draw picture". Boxes are wired together.
Add-on / custom node
Extra boxes made by other people. Useful, but they can have bugs, as UNO's did.
Prompt
The written description we give the image AI, such as "close-up of SITA reading a letter".
Reference photo
A locked picture of a character that the AI copies the face from.
Embedding / fingerprint
A list of numbers that describes a face or a picture, so two can be compared.
Parser
Code that reads a file and splits it into parts, such as scenes, dialogue and characters.
Tunnel
A safe passage that gives a hidden computer a public web address.
Continuity
Keeping things the same from shot to shot: faces, clothes, lighting, props.
Storyboard
A sheet of pictures showing each camera shot of a film, in order, with notes.
